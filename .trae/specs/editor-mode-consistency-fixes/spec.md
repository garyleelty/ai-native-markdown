# 编辑器模式一致性修复 Spec

## Why

继实时预览功能修复后，发现编辑器中还有其他功能在不同模式下存在不一致的问题。这些问题虽然不如实时预览核心功能缺失严重，但也影响用户体验和产品质量。需要系统性地修复这些一致性问题，确保三种编辑模式（源码、实时预览、阅读）下的用户体验尽可能一致。

## 发现的问题

### 1. `_scrollToOffset` 不支持实时预览模式
- **问题**：`_scrollToOffset` 方法只处理了 `EditorMode.source` 和 `else`（阅读模式），没有专门处理实时预览模式
- **影响**：从侧边栏大纲点击跳转到对应位置时，在实时预览模式下可能滚动不准确
- **位置**：`note_panel.dart` 第 248 行

### 2. WikiLink 补全只在源码模式下工作
- **问题**：`_checkWikiLinkTrigger` 方法在非源码模式下直接返回，不触发 wiki link 补全
- **影响**：实时预览模式下无法使用 `[[` 触发笔记链接补全
- **位置**：`note_panel.dart` 第 475 行

### 3. 搜索高亮在实时预览模式下不显示
- **问题**：搜索高亮是通过 `MarkdownHighlightController.buildTextSpan` 实现的，只在源码模式的 TextField 中生效
- **影响**：实时预览模式下搜索功能可用，但看不到高亮的匹配项
- **位置**：`syntax_highlighter.dart` 中的 `MarkdownHighlightController`

### 4. 实时预览模式下的焦点管理
- **问题**：切换到实时预览模式时，没有自动聚焦到编辑器
- **影响**：用户切换模式后需要手动点击才能开始编辑

## What Changes

### 1. 修复 `_scrollToOffset` 支持实时预览模式
- 在实时预览模式下，使用与源码模式类似的策略：通过设置光标位置来触发滚动
- 或者使用估算滚动位置的方式

### 2. 在实时预览模式下支持 WikiLink 补全
- 修改 `_checkWikiLinkTrigger`，让它也支持实时预览模式
- 在 `LiveMarkdownEditor` 中添加 WikiLink 补全的 UI 显示

### 3. 搜索高亮（可选，视复杂度而定）
- 评估在实时预览模式下添加搜索高亮的复杂度
- 如果复杂度太高，可以先不做，记录为待优化项

### 4. 改进焦点管理
- 切换到实时预览模式时自动聚焦到当前编辑行

## Impact

- **修改文件**:
  - `lib/features/editor/widgets/note_panel.dart` - 滚动、wiki link 触发、焦点管理
  - `lib/features/editor/widgets/live_markdown_editor.dart` - wiki link 补全 UI

- **影响范围**: 编辑器模块
- **向后兼容**: 完全兼容，仅修复问题不改变现有 API

## ADDED/MODIFIED Requirements

### 可验证的需求

1. **[ ] 从侧边栏大纲点击跳转到对应位置，在实时预览模式下能正确滚动**
2. **[ ] 实时预览模式下输入 `[[` 能触发 wiki link 补全**
3. **[ ] 实时预览模式下可以正常使用 wiki link 补全选择和插入**
4. **[ ] 切换到实时预览模式时，编辑器自动获得焦点**
5. **[ ] 搜索功能在实时预览模式下可用（查找、替换）**

## 设计决策

### 决策1：WikiLink 补全在实时预览模式下的实现方式
- **问题**：源码模式的 wiki link 补全是叠加在 TextField 上的 Positioned widget
- **方案**：在 `LiveMarkdownEditor` 内部实现 wiki link 补全 UI，使用类似的方式
- **理由**：保持两种模式下的补全体验一致

### 决策2：搜索高亮暂不在实时预览模式中实现
- **问题**：实时预览模式使用自定义渲染，添加搜索高亮需要修改所有渲染方法
- **方案**：搜索功能本身可用（查找、替换），但高亮只在源码模式显示
- **理由**：搜索高亮是增强功能，核心功能（查找、替换）已经可用，后续可以优化
